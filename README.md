# SafeChange — PSM 변경요소관리 AI 비서 MVP

## 사업장 입장 및 선택

서비스는 로그인 없이 첫 화면의 `입장` 버튼으로 시작합니다. 입장 후 좌측 상단의 사업장 선택 메뉴에서 작업할 공장을 고르세요.

- 포항라임공장
- 포항화성공장

선택한 사업장을 기준으로 MOC 건, 이력 및 알림이 분리되어 표시됩니다.

생산·정비 현장 구성원이 첨부된 변경관리 지침의 단계에 따라 교체/변경 여부와 변경관리 등급을 판단하고, 승인·실행·교육·가동 전 점검·종결까지 이어서 처리하는 웹 MVP입니다.

## 실행

요구 환경은 Node.js 22.13 이상입니다.

```bash
npm install
npm run dev
```

브라우저에서 `http://localhost:3000`을 엽니다.

첫 화면에서 `입장`을 누른 뒤, 좌측 상단의 선택 메뉴에서 사용할 사업장을 고릅니다.

검증:

```bash
npm test
npm run build
```

## Vercel 시연 배포

공개 Vercel 시연본은 GitHub `main` 브랜치를 연결해 배포합니다. Vercel에서는 `npm run build:vercel`을 사용하며, 화면에서 작성한 이력은 각 사용자의 브라우저에만 저장됩니다.

- 공개 주소는 `프로젝트명.vercel.app` 형식입니다.
- 실제 D1 데이터베이스, 이메일 발송, 사내 인증은 시연본에 포함하지 않습니다.
- Vercel의 `GET /api/health/db`는 `Browser-local demo` 상태를 반환합니다.
- ChatGPT 사이트는 기존 `npm run build` 경로를 그대로 사용합니다.

## 구현 범위

- 로그인 없이 시작하는 입장 화면과 사업장 선택
- 변경 사유·대상 설비·변경 전후·일반/비상·임시/영구를 포함한 기본정보 작성
- 붙임 2의 설비/절차별 비교 기준을 이용한 단순교체·변경·판단보류 판정
- 붙임 3의 1·2·3등급 기준과 우선순위에 따른 등급 추천 및 근거 보존
- 1·2등급 변경관리위원회 경로와 3등급 파트장 승인 경로 분리
- 실행계획, 16개 검토항목, 공정안전자료, 교육, 가동 전 점검, Punch List 관리
- 임시변경 30일 제한·원상복구 및 비상변경 사후검토 관리
- 업무 기록으로부터 진행상태를 자동 계산하고 수동 단계 넘김을 차단
- 기한 초과·미제출·교육·Punch·임시/비상 후속조치 Reminder와 발송 로그
- 사업장별 대시보드·작성 이력·검토/승인 동기화와 공통 상세조회
- PC 우선 반응형 UI
- 사업장별 진행 3건, 완료 2건, Reminder 2건을 포함한 Mock 데이터

## 구조

- `app/page.tsx`: 전체 MVP 사용자 흐름과 화면
- `app/lib/moc/replacement-criteria.ts`: 붙임 2 교체판정 비교 기준
- `app/lib/moc/replacement-engine.ts`: 단순교체/변경/판단보류 엔진
- `app/lib/moc/grade-rules.ts`: 붙임 3 등급 기준 데이터
- `app/lib/moc/grade-engine.ts`: 등급 추천·우선순위 엔진
- `app/lib/moc/workflow.ts`: 업무 기록 기반 상태 자동 계산
- `app/lib/moc/repository.ts`: 브라우저 저장소와 D1 전환용 저장 계약
- `db/schema.ts`: D1/SQLite 전환 가능한 Drizzle 데이터 모델
- `drizzle/`: DB 마이그레이션
- `tests/`: 판정·검증·상태·저장·화면 계약 회귀 테스트
- `docs/DECISION_RULES.md`: 규칙 설명
- `docs/INTEGRATION.md`: 실제 지침·SSO·메일·사내 시스템 연계

## 데이터 저장

현재 공개 시연본은 선택한 사업장별 답변과 업무 기록을 사용자의 브라우저 로컬 저장소에 보관해 새로고침 후 이어쓰기를 지원합니다. 다른 기기나 사용자와 데이터가 공유되지는 않습니다. 배포 설정에는 Cloudflare D1 논리 바인딩과 추가형 관계형 스키마가 포함되어 있으며, 운영 전 서버 Repository와 사내 인증을 연결해야 합니다.

데이터베이스는 Cloudflare D1(SQLite) 바인딩 `DB`를 사용합니다. 연결 상태는 `GET /api/health/db`로 확인할 수 있으며, D1 바인딩은 배포 환경에서 제공됩니다.

초기 PSM MOC 테이블은 `npm run db:migrate`로 생성합니다. 마이그레이션 이력이 `app_migrations`에 기록되므로 같은 명령을 반복 실행해도 안전합니다.

## 안전 고지

현재 구현은 제공된 변경관리 지침과 붙임·첨부 문서를 소프트웨어 규칙으로 옮긴 시연용 초안입니다. 문서 해석과 현장 적용의 최종 책임을 대신하지 않으므로 실제 PSM 판정 또는 작업 승인에 사용하기 전 PSM 담당자의 조항별 검증, 승인, 회귀 테스트 및 보안 검토가 필요합니다.
