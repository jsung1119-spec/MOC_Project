# 변경관리 지침 기준 MOC 전 과정 개편 설계

## 목표

현재 SafeChange의 `새 변경 판단`과 이후 변경관리 흐름을 회사 변경관리 지침 및 붙임·첨부 양식과 동일한 판단 기준으로 개편한다. 기존 사이트의 디자인, 사업장 분리, 작성 이력, Reminder, 관리자 접근 방식은 유지하며 기존 브라우저 저장 데이터도 계속 열 수 있어야 한다.

기준 문서는 다음 두 파일이다.

- `변경관리_지침.pdf`
- `변경관리_붙임, 첨부.pdf`

문서와 기존 Mock 규칙이 충돌하면 문서를 우선한다. 문서가 최종 판단 권한을 변경관리위원회 또는 담당자에게 부여한 항목은 시스템 자동 확정이 아니라 추천 또는 검토 필요로 표시한다.

## 현행 구조와 Gap

- 화면과 대부분의 상태 처리가 `app/page.tsx`에 집중되어 있다.
- 질문, 단순 판정 규칙, 등급 규칙은 `app/lib/moc.ts`에 함께 있다.
- 현재 질문은 동일 규격, 용량, 재질, 운전조건, Logic, 위험도 등 9개 Mock 질문이다.
- 현재 등급은 `hazard=YES`이면 2등급, `major=YES`이면 1등급으로 정해져 붙임 3의 세부 기준을 반영하지 못한다.
- 현재 비대상 판정은 설비 종류별 비교항목을 모두 확인하지 않으므로 붙임 2의 단순교체 정의와 다르다.
- 후속 상태는 `다음 단계 완료` 버튼으로 수동 전환하며 실제 승인, 교육, 자료 개정, 가동전 점검 데이터와 연결되지 않는다.
- 앱 데이터는 `localStorage`의 `safechange-cases`, `safechange-questions`에 저장된다.
- D1용 Drizzle 스키마는 있지만 건강 상태 확인 외에 변경 건 CRUD API는 연결되어 있지 않다.
- 현재 Vercel 배포는 브라우저 저장 기반 시연 모드이므로 이번 개편에서도 시연 안정성을 우선한다.

## 선택한 접근

브라우저 저장 기반 시연 기능을 완성하되 도메인 규칙, 워크플로, 저장소 인터페이스를 UI에서 분리한다. 향후 D1 저장 API를 붙일 때 판정 엔진과 화면을 바꾸지 않고 저장소 구현만 교체할 수 있게 한다.

이번 작업에서는 페이지 전체를 재작성하지 않는다. 변경관리 기능과 직접 관련된 로직만 작은 모듈로 분리하고 현재 CSS와 화면 골격을 재사용한다.

## 도메인 모델

### 변경 기본정보

변경 건은 다음 값을 가진다.

- 제목, 변경 사유, 변경 내용
- 대상 설비 또는 공정
- 변경 대상 분야
- 변경 전 상태, 변경 후 상태
- 정상변경 또는 비상변경
- 임시 또는 영구
- 임시변경 시작일과 종료일

임시변경은 종료일이 필수이고 시작일로부터 30일을 초과할 수 없다.

### 변경판정

붙임 2를 하나의 `replacementCriteria` 데이터셋으로 관리한다. 설비 또는 물질 종류별로 ● 표시된 비교항목만 사용자에게 보여 준다.

- 적용 비교항목이 모두 `SAME`이면 `SIMPLE_REPLACEMENT`
- 하나 이상 `DIFFERENT`이면 `CHANGE`
- 하나 이상 `UNKNOWN`이 있고 다른 변경 신호가 없으면 `UNDETERMINED`
- 상충되거나 필수 비교항목이 없으면 `UNDETERMINED`

정비·운전·부수공정 항목은 항목 자체를 시행하는지가 변경 신호가 된다. 결과에는 적용 항목과 선택값, 일치 또는 변경 근거, 문서 출처를 저장한다.

기존 `isMocTarget=false` 자료는 읽을 때 `SIMPLE_REPLACEMENT`로 호환한다.

### 등급판정

붙임 3의 모든 행을 `gradeRules`로 관리한다. 각 규칙은 코드, 분야, 설명, 등급, 사용자 확인 입력, 근거 문서를 가진다.

매칭된 규칙의 등급 중 숫자가 가장 낮은 등급을 가장 높은 등급으로 선택한다. 예를 들어 2등급과 3등급 규칙이 모두 매칭되면 추천 등급은 2등급이다. 규칙이 매칭되지 않거나 답변이 불확실하면 `UNDETERMINED`로 두고 위원회 검토가 필요하다고 표시한다.

결과는 추천 등급이며 최종 등급은 담당자 또는 변경관리위원회가 조정할 수 있다. 추천 등급과 최종 등급, 조정 사유를 별도로 저장한다.

위험성평가는 1·2등급이면 HAZOP, 3등급이면 Check List를 기본 추천한다. 권한 있는 사용자가 다른 기법과 변경 사유를 기록할 수 있다.

## 후속 업무 데이터

변경 건에 다음 하위 데이터를 둔다.

- 변경 요청/승인서
- 변경관리 실시 계획서
- 16개 변경 검토사항
- 공정안전자료 영향 및 개정 상태
- 교육 계획과 실시 내역
- 가동전 점검, Punch List, 재점검 결과
- 변경관리위원회 개최 및 심의 결과
- 임시변경 기술검토, 현장 표시, 원상복구
- 비상변경 선조치 및 사후 승인
- 상태 변경 이력

각 체크리스트 항목은 해당 여부, 담당자 또는 담당부서, 예정일, 완료일, 확인 여부, 비고를 공통으로 지원한다.

## 워크플로

일반 변경은 다음 상태를 사용한다.

1. `DRAFT`
2. `JUDGMENT_PENDING`
3. `SIMPLE_REPLACEMENT` 또는 `CHANGE_CONFIRMED`
4. `GRADE_PENDING`
5. `REVIEW_PENDING`
6. `COMMITTEE_REVIEW`(1·2등급 또는 검토 필요 시)
7. `APPROVAL_PENDING`
8. `APPROVED`
9. `IMPLEMENTING`
10. `DOCUMENT_UPDATE`
11. `TRAINING`
12. `PRE_STARTUP_CHECK`
13. `CORRECTIVE_ACTION`(부적합 또는 Punch List 미완료 시)
14. `COMPLETED`

3등급은 위원회 상태를 건너뛰고 설비운전파트장 승인으로 진행할 수 있다. 1·2등급은 위원회 심의와 승인이 없으면 변경 실시로 넘어갈 수 없다.

비상변경은 선조치를 기록할 수 있으나 이후 요청/승인서, 위험성평가, 사후 검토와 승인을 완료해야 한다. 임시변경은 30일 만료일, 기술검토서, 위험성평가, 현장 표시, 교육, 원상복구를 관리한다.

상태는 사용자가 임의로 다음 단계로 넘기지 않는다. `deriveWorkflowStatus(case)`가 실제 데이터 완료 여부를 확인해 현재 상태를 산출한다.

## 완료 조건

다음 조건을 모두 충족해야 `COMPLETED`가 된다.

- 요구되는 승인 완료
- 변경 작업 완료
- 개정이 필요한 공정안전자료 모두 개정 완료
- 필수교육 완료
- 가동전 점검 최종 적합
- Punch List 및 보완사항 완료
- 해당되는 변경 검토사항 완료

미충족 상태에서 완료를 요청하면 `validateCompletion`이 누락 항목과 조치 방법을 반환한다.

## UI

기존 레이아웃, 색상, 폰트, 카드와 테이블 스타일을 유지한다.

- 새 변경 판단 첫 화면에 기본정보 폼을 둔다.
- 분야와 설비 종류에 따라 붙임 2 비교질문을 한 화면 한 질문 방식으로 보여 준다.
- 변경 판정 후 변경 건만 등급 기준 질문으로 이동한다.
- 결과 화면에 판정, 추천 등급, 근거, 지침 조항, 위원회 필요 여부, 위험성평가 추천을 보여 준다.
- 상세 화면은 기본정보, 판정, 검토/승인, 실시계획, 자료 최신화, 교육, 가동전 점검, 완료 탭 또는 카드로 구성한다.
- 대시보드, 작성 이력, 검토/승인, Reminder는 새 상태 라벨과 같은 데이터를 사용한다.
- 단순교체는 결과와 근거를 저장하고 일반 변경관리 후속 단계는 열지 않는다.

## 저장 호환

저장 형식에 `schemaVersion`을 추가한다. `normalizeMocCases`가 기존 자료를 최신 형식으로 변환하며 기존 제목, 사업장, 답변, 판단, 초안은 유지한다. 새 필드는 선택값 또는 명확한 기본값으로 채운다.

브라우저 저장은 저장소 인터페이스를 통해 수행한다. D1 스키마에는 JSON으로 보존할 수 있는 복합 양식 또는 정규화된 하위 테이블을 추가하되, 이번 시연에서 화면은 브라우저 저장소를 기본 사용한다.

## 오류 처리

- 필수 기본정보 누락: 해당 필드 강조 및 다음 단계 제한
- 임시변경 30일 초과: 종료일 오류 및 저장 제한
- 비교항목 불확실 또는 상충: 판정불가와 위원회 검토 안내
- 등급 규칙 미매칭: 자동 등급 확정 금지
- 승인·교육·점검 누락: 후속 상태 전환 제한과 누락 목록 표시
- 부적합 또는 미완료 Punch List: 완료 제한
- 이전 저장자료: 자동 변환 실패 시 원본을 덮어쓰지 않고 복구 안내

## 테스트와 검증

판정 엔진과 워크플로는 UI 없이 테스트한다.

- 모든 비교요소 동일 → 단순교체
- 하나 이상 다름 → 변경
- 1등급, 2등급, 3등급 각각 매칭
- 2+3 동시 매칭 → 2등급
- 1+2 동시 매칭 → 1등급
- 불확실 또는 규칙 없음 → 위원회 검토
- 임시변경 30일 초과 → 검증 오류
- 교육 또는 가동전 점검 미완료 → 완료 불가
- 기존 저장 자료 → 최신 모델 변환

완료 전 typecheck, lint, unit test, 두 빌드 경로, 브라우저의 단순교체·3등급·2등급·임시변경 대표 시나리오를 검증한다.
