# 실제 업무지침 및 사내 시스템 연계 가이드

## 지침·질문·규칙 버전

붙임 2 비교기준과 붙임 3 등급기준은 현재 TypeScript 데이터로 분리되어 있습니다. 운영 단계에서는 `Guideline`, `DecisionRule` 테이블에 버전, 시행일, 승인자와 활성 상태를 추가하고, 신규 판정 시작 시 적용 버전을 고정합니다. 이미 진행 중인 건의 기준을 소급 변경하지 않습니다.

## 저장소 전환

화면은 현재 브라우저 Repository를 사용합니다. `app/lib/moc/repository.ts` 계약을 유지한 채 D1 구현체로 교체하면 화면 로직을 바꾸지 않고 서버 저장으로 전환할 수 있습니다.

1. Cloudflare 프로젝트에 D1 데이터베이스와 `DB` 바인딩을 생성합니다.
2. `drizzle/0000_initial.sql`, `drizzle/0001_guideline_moc.sql` 순서로 적용합니다.
3. Route Handler에서 세션의 사용자·사업장을 검증합니다.
4. 저장·조회·삭제를 D1 Repository에 연결합니다.
5. `/api/health/db`와 실제 생성/재조회 통합 테스트를 실행합니다.

추가 마이그레이션은 기존 테이블을 삭제하지 않고 JSON 업무기록과 버전 필드를 더하는 방식입니다. PostgreSQL/Neon 코드는 사용하지 않습니다.

## 인증과 권한

운영 전 사내 SSO(OIDC/SAML)로 교체하고 서버에서 `USER`, `REVIEWER`, `ADMIN` 권한, 사용자 소속 사업장과 건별 소유권을 검증합니다. 관리자 공통 비밀번호 `0000`은 시연 전용이므로 운영 환경에서는 제거합니다.

## 메일

개발 환경은 Reminder 발송 로그만 기록합니다. 사내 SMTP 또는 메일 API 어댑터를 연결할 때 `mocCaseId + reminderType + scheduledDate`를 중복 방지 키로 사용하고, 재시도·실패 사유·수신자·발송시각을 감사 로그에 남깁니다.

## 문서·설비 시스템

- EDMS: 승인 신청서, 위험성평가서, 가동 전 점검표와 첨부파일을 관리번호로 전송
- ERP/CMMS: 작업오더, 설비번호, 책임자, 계획/완료일 양방향 동기화
- DCS/도면 시스템: P&ID, Logic, Set Point와 공정안전자료 개정번호 연결
- 교육 시스템: 교육 대상자, 참석 결과, 이수 증빙 연계
- 사내 LLM: 규칙 판정은 결정론적 엔진으로 유지하고 서술 초안·누락 점검만 Provider 인터페이스로 위임

## 운영 전 필수 보강

서버 세션, 사업장 권한, 감사 로그, 전자서명, 첨부파일 악성코드 검사, 백업/복구, 보유기간, 규칙 변경 이중 승인, 동시 수정 충돌 방지, 장애 알림과 PSM 담당자 인수시험을 적용해야 합니다.
